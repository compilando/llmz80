# Amstrad CPC 464/6128 / CPCtelera generation contract

Generate one self-contained `main.c` compiled by the repository's CPCtelera Makefile and SDCC toolchain.

## Output

- Return raw C only. No Markdown fences or explanation.
- Include exactly the platform header needed: `#include <cpctelera.h>`.
- Do not include local headers, create other source files, reference external assets, or change the build.
- Define sprites, palettes, maps, strings, and lookup tables directly in this file as small static arrays.
- Use CPCtelera APIs only when their exact signature appears below or in a retrieved compiling example.

## Mandatory program shape

```c
#include <cpctelera.h>

void main(void) {
    /* declarations before statements */
    cpct_disableFirmware();
    cpct_setVideoMode(1);
    cpct_clearScreen(0x00);
    while (1) { }
}
```

`cpct_disableFirmware()` must be the first executable call in `main` (declarations may precede it). Set the video mode before drawing.

## Verified graphics and video signatures

```c
cpct_setVideoMode(mode);                         /* mode: 0, 1, or 2 */
cpct_clearScreen(colour_pattern);
cpct_setPalette(palette, count);
cpct_setPALColour(pen, hardware_colour);
u8* p = cpct_getScreenPtr(CPCT_VMEM_START, x_byte, y);

cpct_drawSprite(sprite, p, width_bytes, height);
cpct_drawSpriteMasked(sprite, p, width_bytes, height);
cpct_drawSpriteBlended(p, height, width_bytes, sprite); /* unusual order */
cpct_drawSolidBox(p, colour_pattern, width_bytes, height);

u8 m0 = cpct_px2byteM0(pixel0, pixel1);
u8 m1 = cpct_px2byteM1(pixel0, pixel1, pixel2, pixel3);
```

There is no `cpct_px2byteM2`; use direct bit patterns in mode 2. `x_byte` and sprite width are measured in video-memory bytes, not logical pixels. The visible screen is 80 bytes wide in every mode and 200 lines high. Keep `x_byte + width_bytes <= 80` and `y + height <= 200`.

Palette entries use CPC hardware constants such as `HW_BLACK`, `HW_BLUE`, `HW_BRIGHT_BLUE`, `HW_RED`, `HW_MAGENTA`, `HW_GREEN`, `HW_CYAN`, `HW_YELLOW`, and `HW_BRIGHT_WHITE`.

## Verified text signatures

Set character colours before drawing text:

```c
cpct_setDrawCharM0(foreground_pen, background_pen);
cpct_setDrawCharM1(foreground_pen, background_pen);
cpct_setDrawCharM2(foreground_pen, background_pen);

cpct_drawStringM0("TEXT", p);
cpct_drawStringM1("TEXT", p);
cpct_drawStringM2("TEXT", p);

cpct_drawCharM0(p, 'A');
cpct_drawCharM1(p, 'A');
cpct_drawCharM2(p, 'A');
```

The `drawChar` calls take video memory first; the `drawString` calls take the string first. Use the M0/M1/M2 family matching the selected video mode.

Call `cpct_scanKeyboard()` or `cpct_scanKeyboard_f()` once per loop before checking keys. `cpct_getKeyASCII`, `cpct_waitUntilKeyPressed`, and `cpct_waitUntilKeyReleased` do not exist in this CPCtelera version; never use them.

## Verified memory, timing, and random signatures

```c
cpct_memset(destination, byte_value, size);
cpct_memcpy(destination, source, size);
cpct_waitVSYNC();
cpct_waitHalts(count);

cpct_setSeed_glfsr16(seed16);
random_byte = cpct_getRandom_glfsr16_u8();
/* LCG requires an entropy argument: */
random_byte = cpct_getRandom_lcg_u8(entropy_byte);
```

Never call `cpct_setRandom_lcg_u8()` and never call `cpct_getRandom_lcg_u8()` with zero arguments.

## SDCC and machine constraints

- Use CPCtelera types `u8`, `i8`, `u16`, `i16`, `u32`.
- Declare variables at the beginning of a function or block; do not declare a loop variable inside `for (...)`.
- Use integer/fixed-point arithmetic. No `float`, `double`, heap allocation, file I/O, `printf`, recursion, or large local arrays.
- Never use runtime division or modulo (`/`, `%`, `/=`, `%=`). In this build they pull SDCC helpers with an incompatible calling convention. Use shifts/masks for powers of two, lookup tables, or bounded subtraction (including decimal formatting and random ranges).
- A signed `i16` cannot hold full-screen CPC coordinates in 8.8 fixed point: for example, `160 << 8` overflows. Prefer signed 10.6 (`FP_SHIFT 6`) for 320x200 coordinates, or use `i32` when 8.8 is required. Check every shifted constant against its destination type.
- SDCC may emit warning 158 for an implicit constant conversion such as `const u8 y = 200 - height`; use an explicit `(u8)` cast after checking that the value is within 0..255.
- Prefer `static const u8` for immutable data and small global/static state for the game.
- Clear/redraw only the regions that changed when practical. Use `cpct_waitVSYNC()` for frame pacing.
- Handle held keys intentionally: use previous-key state for one-shot actions.
- Keep all sprite/map data and code comfortably within the CPC program memory budget.

Before answering, check every external symbol, signature, video-mode suffix, byte width, coordinate bound, include, and data dependency. Output only the final C source.
