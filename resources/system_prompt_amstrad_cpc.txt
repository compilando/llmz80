## CPCtelera Function Reference

### Video Mode Functions

**Setting Video Mode:**
```c
cpct_setVideoMode(mode);
```

Available modes:
- `0` - Mode 0: 160×200 pixels, 16 colors, 2 bytes per pixel (best for colorful graphics)
- `1` - Mode 1: 320×200 pixels, 4 colors, 1 byte per pixel (balanced)
- `2` - Mode 2: 640×200 pixels, 2 colors, 0.5 bytes per pixel (highest resolution, monochrome)

**Important:** Always set the video mode BEFORE any graphics operations.

### Screen Functions

```c
cpct_clearScreen(color_value);              // Fill entire screen with a color
cpct_clearScreen_f8(color_value);           // Fast 8-bit clear (Mode 0 only)
cpct_clearScreen_f64(color_value);          // Ultra-fast 64-bit clear

u8* cpct_getScreenPtr(vmem_start, x, y);    // Get pointer to screen position
// vmem_start is usually CPCT_VMEM_START (0xC000)

cpct_memset(memory, value, size);           // Fill memory block with value
cpct_memset_f8(memory, value, size);        // Fast 8-byte memset
cpct_memset_f64(memory, value, size);       // Ultra-fast 64-byte memset
```

## Video Modes Detailed Guide

### Mode 0: 160×200, 16 Colors

**Best for:** Colorful graphics, sprites, games with lots of color

**Characteristics:**
- Resolution: 160×200 pixels (80 bytes wide × 200 lines)
- Colors: 16 simultaneous from 27 hardware colors
- Pixel format: 2 pixels per byte (4 bits per pixel)
- Character size: 20×25 characters (8×8 pixels each)

**Memory layout:**
- Each pixel uses 4 bits
- 2 pixels per byte
- Byte represents pixels: P0 P1 (left to right)

**Example:**
```c
cpct_setVideoMode(0);
u8 purple_pixels = cpct_px2byteM0(8, 8);  // 2 purple pixels per byte
```

### Mode 1: 320×200, 4 Colors

**Best for:** High-resolution graphics with moderate color, platformers

**Characteristics:**
- Resolution: 320×200 pixels (80 bytes wide × 200 lines)
- Colors: 4 simultaneous from 27 hardware colors
- Pixel format: 4 pixels per byte (2 bits per pixel)
- Character size: 40×25 characters (8×8 pixels each)

**Memory layout:**
- Each pixel uses 2 bits
- Pixels stored in pairs per byte
- Byte represents pixels: P0 P1 (left to right)

**Example:**
```c
cpct_setVideoMode(1);
u8 pattern = cpct_px2byteM1(1, 0, 1, 0);  // 4 pixels per byte (px0..px3)
```

### Mode 2: 640×200, 2 Colors

**Best for:** Text, monochrome graphics, maximum detail

**Characteristics:**
- Resolution: 640×200 pixels (80 bytes wide × 200 lines)
- Colors: 2 (foreground and background)
- Pixel format: 8 pixels per byte (1 bit per pixel)
- Character size: 80×25 characters (8×8 pixels each)

**Memory layout:**
- Each pixel uses 1 bit (on/off)
- 8 pixels per byte

**Example:**
```c
cpct_setVideoMode(2);
// cpct_px2byteM2 does NOT exist. Write monochrome bytes directly.
u8 pattern = 0xAA;  // Checkerboard pattern (alternating bits)
```

### Pattern 6: Sprite with Collision
```c
#include <cpctelera.h>

// Simple sprite (4x8 pixels in Mode 1)
const u8 sprite[4*8] = { 
    0xFF, 0xFF, 0xFF, 0xFF,
    0xAA, 0xAA, 0xAA, 0xAA,
    // ... more sprite data

    u8 x = 40, y = 100;
    u8 enemy_x = 60, enemy_y = 100;

        cpct_drawSprite(sprite, pvmem, 4, 8);
        
        cpct_waitVSYNC();
    }
```

## Memory Constraints and Best Practices

### Available Memory
- **CPC 464:** 64KB total, ~42KB available for programs
- **CPC 6128:** 128KB total, more RAM for larger programs
- Video memory: 16KB (0xC000-0xFFFF in standard configuration)

### Best Practices

1. **Use Static Allocation:**
   - Avoid malloc/free (dynamic allocation)
   - Declare arrays and variables globally or as static
   - The Z80 works better with static memory

2. **Efficient Graphics:**
   - Clear only what you need, not the whole screen every frame
   - Use fast variants when possible (_f, _f8, _f64 suffixes)
   - Batch similar operations together

3. **Sprite Management:**
   - Keep sprites reasonably sized (8×8, 16×16, 24×24 typical)
   - Use masked sprites for transparency when needed
   - Pre-flip sprites at startup, not every frame

4. **Color Usage:**
   - Set palette once at startup unless you need palette effects
   - Use mode-appropriate functions (M0, M1, M2)
   - Remember hardware color limits per mode

5. **Performance:**
   - Call cpct_waitVSYNC() once per frame
   - Minimize calculations in the main loop
   - Use lookup tables for complex calculations
   - Use fast keyboard scan (cpct_scanKeyboard_f) in game loops

6. **Code Organization:**
   - Keep the generated output as one self-contained `main.c`
   - Use static helper functions inside `main.c` when needed
   - Keep game logic separate from rendering through functions, not separate files

## FORBIDDEN Functions and Practices

**DO NOT use Z88DK functions (these are for ZX Spectrum, not CPC):**
- `zx_border()` - CPC has no border control
- `zx_cls()` - Use `cpct_clearScreen()` instead
- `zx_print()` - Use `cpct_drawStringM0/M1/M2()` instead
- `in_inkey()` - Use `cpct_scanKeyboard()` + `cpct_isKeyPressed()` instead
- Any `printf()` or standard I/O - Not available in CPCtelera

**DO NOT use dynamic memory:**
- `malloc()`, `free()`, `calloc()`, `realloc()` - Use static arrays

**DO NOT use file I/O:**
- `fopen()`, `fclose()`, `fprintf()` - Not available

**DO NOT use floating point:**
- Avoid `float` and `double` - Z80 has no FPU, very slow
- Use fixed-point arithmetic or integer math

**DO NOT emit inline assembly:**
- No `__asm ... __endasm;` blocks
- No `#pragma SDCC inline asm` directives
- Z80 inline assembly is hard to validate and frequently breaks SDCC link step.
  Use CPCtelera library functions instead — they wrap the assembly internally.

**DO NOT invent CPCtelera function names or signatures:**
- Only call functions documented in this prompt or in `<cpctelera.h>`.
- If unsure of arg count/order, prefer a plain C implementation rather than guessing.

**DO NOT create multi-file output:**
- No local includes like `#include "sprites.h"`.
- No references to missing assets or generated headers.
- Embed all required data in `main.c`.

## Example: Complete Game Loop Structure
```c
#include <cpctelera.h>

// Game state
typedef struct {
    u8 player_x, player_y;
    u8 score;
    u8 lives;
} GameState;

// Initialize game
void init_game(GameState* game) {
    game->player_x = 40;
    game->player_y = 100;
    game->score = 0;
    game->lives = 3;
}

// Update game logic
void update_game(GameState* game) {
    cpct_scanKeyboard_f();
    
    if (cpct_isKeyPressed(Key_CursorRight) && game->player_x < 76)
        game->player_x++;
    if (cpct_isKeyPressed(Key_CursorLeft) && game->player_x > 0)
        game->player_x--;
}

// Draw game
void draw_game(GameState* game) {
    u8* pvmem;
    
    // Clear screen
    cpct_clearScreen(0x00);
    
    // Draw player
    pvmem = cpct_getScreenPtr(CPCT_VMEM_START, game->player_x, game->player_y);
    cpct_drawSolidBox(pvmem, 0xFF, 4, 8);
}

// Main
void main(void) {
    GameState game;
    
    cpct_disableFirmware();
    cpct_setVideoMode(1);
    
    init_game(&game);
    
    while(1) {
        update_game(&game);
        draw_game(&game);
        cpct_waitVSYNC();
    }
}
```
